# 产品配件计算器

客户订的是一套产品，实际要发的是一整套配件。

销售报数量的时候，主件通常不会忘——门框、门扇记得住。真正被漏掉的是那些不起眼的东西：
螺丝包少一包、密封条没算、包装箱漏了、说明书忘了放。等到仓库备货或者客户安装时才发现，
要么补发，要么上门，成本比漏掉的那点配件高得多。

这个工具就干一件事：**把一套产品需要的配件一次列全，并且明确告诉你哪一项漏了。**

## 它怎么防漏

每个配件在产品定义里都有 `required` 标记：

- 标了 `必配` 的配件，如果算出来数量是 0，结果区会**红色警告**，并写明是哪一项
- 没标的算 `选配`，数量为 0 是正常情况，不报警

这一条是整个工具的立身之本。数量算错可以改，配件漏了会变成售后。

## 后续迭代方向

这份工具的终点不是"算出数量"，是**让数量直接进入报价和生产**。规划如下，按顺序做：

| 阶段 | 要解决的问题 | 大概做法 |
|---|---|---|
| 1. 当前 | 一套产品的配件算全、不漏 | 已完成 |
| 2. 合并导出 | 一个订单常有多个产品，现在要一个个算、手动抄到一张表 | 允许把多次计算结果累加成一个订单清单，同配件自动合并数量 |
| 3. 接报价 | 数量算完还要查单价、算小计、加税 | 在配件定义里加 `price`，导出带金额的报价版 CSV |
| 4. 接生产 | 报价通过后要转成备料单、工单 | 导出按分组拆分的生产用表，保留配件编码字段 |

第 2 阶段是下一个要做的。第 3、4 阶段依赖真实的价格口径和生产字段，
在这些数据定下来之前不动手——**先有规则，再写代码**。

## 为什么仓库里没有产品数据

同一套引擎可以算推拉门、护栏、家具、五金件、型材。变的是配件构成和系数，
不变的是输入校验、逐项取整、损耗、分组和漏配检查。

把数据抽走之后这份代码可以开放，而具体产品配什么、系数是多少，留在各自公司内部。

真实数据这样接进来：

```bash
cp data/product-master.example.js data/product-master.js
```

然后把 `index.html` 末尾引用的 `product-master.example.js` 改成 `product-master.js`。

没有 `product-master.js` 时页面会明确提示「产品数据未加载」，不会静默算出 0 套。

## 结构

```
index.html                     入口，双击即开
css/app.css                    样式，无框架
js/engine.js                   计算引擎（无 DOM、无数据、无依赖）
js/app.js                      界面控制器（不含任何公式）
data/product-master.example.js 示例产品定义（虚构数据）
data/config.js                 展示层设置
tests/offline-smoke-test.cjs   引擎的离线验证（15 条用例）
规则说明.md                     配件构成表与改动记录
```

三层职责分得很硬：

| 层 | 允许改什么 | 不允许做什么 |
|---|---|---|
| `engine.js` | 校验、取整、分组、漏配检查、导出格式 | 认识任何具体产品 |
| `product-master.js` | 配件、系数、必配标记、单位 | 碰 DOM |
| `app.js` | 表单、渲染、按钮 | 出现任何公式 |

## 写一条配件

```js
{
  id: 'seal-strip',
  label: '密封条',
  unit: '米',
  group: '辅料',
  required: true,              // 必配：算出来是 0 会报警
  per: { widthM: 2 },          // 每条门两侧各一条
  note: '两侧各一条',
}
```

数量算法：

```
数量 = Σ(per[输入id] × 该输入值) + fixed
      × (1 + overage)
      然后按 rounding 取整
```

| 字段 | 作用 |
|---|---|
| `per` | 按哪个输入乘多少。`{ quantity: 2 }` 是每套两个；`{ widthM: 1 }` 是每米一根 |
| `fixed` | 与数量无关的固定用量，比如说明书每单一份 |
| `overage` | 备损比例。和输入里的损耗率不叠加，两者用途不同 |
| `rounding` | `ceil` / `floor` / `round` / `none`，默认向上 |
| `required` | 漏配检查的依据 |

## 导出

算完之后两个按钮：

- **导出 CSV** —— 带 BOM，Excel 打开中文不乱码。列为：分组、配件、数量、单位、备注
- **复制清单** —— 纯文本，形如 `[五金] 上滑轮：20 个`，可直接贴进聊天窗口

CSV 就是给第 2、3 阶段铺的路：先把数据变成一张能粘贴的表，再谈金额和工单。

## 取整为什么要防浮点噪声

`10 / 0.5` 在浮点里可能是 `20.000000000000004`，直接向上取整会多算一件。
引擎在取整前先减 `1e-9`，这一项有专门的测试用例。
